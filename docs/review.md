# Refactor and review

Reviewed the copied game source while preparing a maintainable repository. The original development directory was left in place; earlier scripts and snapshots are retained under `history/`.

## Findings addressed

| Problem                                                                                                                                                        | Change and regression coverage                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inline HTML contained the full game loop and CSS, making review and targeted edits difficult.                                                                  | Extracted maintained `app.js` and `styles.css`, preserving classic-script loading order and local static use. The harness reads the actual script tags rather than assuming an inline script.                               |
| Changing Shift while holding a movement key could leave the uppercase key stuck; keyboard actions could interfere with form controls or browser shortcuts.     | Movement follows physical key codes; release uses the same normalized key. Form controls, editable text, and Ctrl/Command/Alt combinations are excluded. Blur, hidden tabs, form focus, and touch cancellation clear input. |
| Travel, reset, and the landing-photo action could bypass the first-run intro.                                                                                  | UI actions pass through one mission-start gate. The requested action runs after the clip ends or is skipped.                                                                                                                |
| Reset could retain first-person/overview/free-flight state or stale camera smoothing values; the displayed driving mode could disagree with the actual state.  | Reset restores the orbit camera, route and sample state. Mode text and ARIA state are synchronized with the selected driving mode.                                                                                          |
| A sidebar action could focus the game while leaving its canvas outside the visible viewport.                                                                   | Returning to play scrolls the canvas into view only when it is clipped or offscreen, then restores keyboard focus.                                                                                                          |
| Closing the intro dialog outside the normal buttons, an unsupported modal API, or a late failed playback promise could strand or unexpectedly resume the game. | Added guarded completion, native-close handling, fallback behavior, retryable interrupted playback, and playback-attempt tracking. Tests cover completion, pause/resume, Skip, Escape, errors, and stale events.            |
| A discontinuous rover position could create a trail between destinations and rotate wheels as if the entire jump had been driven.                              | Pose reset clears wheel contact history while preserving existing tracks. Large discontinuities reset pose automatically. Full mission reset also clears tracks and wheel spin.                                             |
| Suspension movement changed chassis height without invalidating the cached rover shadow.                                                                       | Shadow caching includes the rendered model transform. Identical poses avoid redraws; a changed chassis altitude redraws the shadow.                                                                                         |
| Terrain construction allocated large intermediate JavaScript arrays before copying them into GPU buffers.                                                      | The renderer builds a preallocated `Float32Array` and uploads it directly. Vertex order and heights are preserved within the existing Float32 upload precision.                                                             |
| Driving bounds captured the original scale rather than following the current terrain dimensions.                                                               | Bounds are derived from current world dimensions. Tests exercise a temporary scale change and restore it.                                                                                                                   |
| Older tests assumed superseded waypoint counts, internal source layout, and UI strings.                                                                        | Replaced them with focused Node tests and shared DOM/GL and MOLA fixtures. Original test scripts remain in development history.                                                                                             |

## Verification

The maintained Node suite covers intro transitions, input/reset/camera state, geographic conversions, native-grid import and rejection cases, route registration and sequential progression, wheel contact and track behavior, teleport resets, shadow invalidation, and finite camera transforms. It runs from the current source tree without requiring a generated build.

These tests mock the browser DOM and WebGL driver. They do not validate browser media decoding, shader compilation, texture appearance, accessibility in a screen reader, or real hardware frame rates.

The separate Chromium smoke check successfully exercised WebGL startup and shader compilation, intro video decoding and natural completion, pause/resume and Skip, the generated background, input isolation, rover driving, camera modes, reset, and mobile layout without horizontal overflow. Screenshots were inspected. This run used software WebGL; it is not a hardware performance benchmark. The reproducible browser check is `npm run test:browser`.

The MOLA parser uses an explicitly synthetic affine binary fixture for endian, stride, geography, and interpolation checks. The fixture is never stored as a real NASA terrain asset. Passing those tests does not establish the scientific accuracy of the image-derived fallback or screenshot route registration.

Remaining limits are described in the game's provenance UI, [README](../README.md), and [asset notes](../ASSETS.md). The map is locally projected, MOLA is coarse relative to a rover, screenshot-derived route coordinates are approximate, and rocks/traction/suspension are illustrative.
